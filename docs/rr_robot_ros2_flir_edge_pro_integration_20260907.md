# ROS 2巡检小车与FLIR ONE Edge Pro接入方案

日期：2026-09-07。本文为待实现的接口设计，不是已经编译、运行或实机验证的ROS软件包。没有改动已有导航、模型、计数规则或实验结果。

## 1. 已知条件与首版边界

| 条件 | 当前结论 |
|---|---|
| 小车导航 | 已有，使用ROS 2；ROS发行版和是否Nav2尚未知 |
| 相机 | 沿用原文FLIR ONE Edge Pro，暂不采购替代型号 |
| 车载电脑 | 尚未到货；不预设Ubuntu版本、Jetson或独立显卡 |
| 首版工作方式 | 导航到站、确认停稳、采集固定窗口、输出RR或不可判定、继续巡检 |
| 科研任务 | 同时保存原始数据、机器人运动、身份、参考录像和全部失败访问 |

先完成停车测量。行驶画面可以保存为研究数据，不能把历史离线R²直接解释为车载移动测量性能。现有算法中的未获验证跟踪、尺度自适应和运动补偿分支不默认启用。

## 2. 相机到ROS 2的实际链路

优先验证以下链路，并以实际SDK支持为准：

```text
FLIR ONE Edge Pro
  -> 兼容手机/平板上的FLIR SDK采集程序
  -> 经测试的手机至车载机数据连接
  -> 车载接收与原始记录进程
  -> ROS 2图像、帧元数据和设备状态
  -> 鼻孔定位、温度序列、窗口RR结果
```

FLIR官方提供Android/iOS等平台的移动SDK；其Android文档包含ONE Edge无线发现和流式采集示例、Edge Pro相关修复记录。[1][2] 这些说明支持从官方移动SDK入手，但不保证当前手机、固件、SDK组合已经可用。文档中的旧版本号只是支持证据，不是建议安装的版本。

### 2.1 先做采集能力验证

1. 用当前官方App录制一段连续视频，检查导出后是否包含温标、帧时间信息、纯热像及混合显示信息。记录App版本、固件、调色板、量程和增强设置。
2. 在兼容手机上运行官方无线相机采集示例，确认发现、连接、连续取帧和断线恢复。SDK申请和许可由设备使用者按官方流程办理。
3. 分别确认能否取得渲染图像、逐像素温度、设备状态和时间信息。无法取得的字段标为不可用，不根据画面外观推断支持。
4. 核对手机连接相机时，能否同时向车载机传输数据。USB网络共享、USB以太网或其他连接只作为待验证选项；不默认手机可以同时连接两个Wi-Fi网络。
5. 持续录制一段覆盖多次测量的台架数据，检查丢帧、重复帧、时钟跳变、手机温升、存储和供电。初次可用30分钟作为工程试验长度，之后需验证完整巡检时长。

相机USB接口不能未经验证当作UVC摄像头接口；也不预设RTSP地址。若厂家另有经确认支持该型号的桌面接口，可替换手机采集端，保持下游数据契约不变。

### 2.2 两条数据路线不能混用

| 路线 | 温度信号来源 | 注意事项 |
|---|---|---|
| 旧方案兼容路线 | 伪彩色图像，经原随机森林映射 | 保持BGR输入语义；检查调色板、温标变化和图像处理；新导出不能直接假设与旧模型同分布 |
| 原生测温路线，待SDK确认 | 官方测温接口返回的逐像素值 | 明确单位和无效值，核对测温网格与检测图像的几何对应；不再把温度矩阵送入颜色回归模型 |

原生测温可以避免颜色反演这一环节，但不保证自动提高RR准确率，仍需用同窗参考比较。显示图像、插值/增强图像和原生热网格的尺寸不同，不可仅按相同像素坐标取ROI。原有固定半径20也不能跨分辨率原样移植。

只有普通MP4时，仍可先完成上车录像和离线实验。它不是已经实现实时测温接入；屏幕录制尤其不能当作测温原始档案。

## 3. ROS 2侧职责划分

以下名称是拟定接口名，尚不是小车上实际存在的话题。首次可以合并为少量进程，不必为了形式拆成大量节点。

| 建议模块 | 输入 | 输出与职责 |
|---|---|---|
| `thermal_bridge` | 手机数据或离线文件 | 帧、时间和相机状态；校验顺序；原始数据记录 |
| `rr_estimator` | 带时间戳的帧、目标及窗口边界 | 复用确认的YOLO11n-Pose权重与RR流程；输出帧级温度和事件证据 |
| `rr_measure_server` | 单次测量任务、图像与运动状态 | 停稳、锁定、窗口管理、超时和取消；不直接控制底盘速度 |
| `rr_mission_adapter` | 原有导航状态与RR任务结果 | 到站后请求测量；按安全与任务规则重试或继续 |
| `rr_recorder` | 原始数据、状态事件和结果 | 索引、完整性检查、本地落盘；可与bridge合并 |

导航适配器只对接厂家已有接口。若采用Nav2，可用航点任务执行插件挂接测量；ROS 2本身不等于已装Nav2。[3] 未核实前不发布`cmd_vel`，不修改导航参数或急停逻辑。

### 3.1 建议话题

| 接口 | 建议内容 |
|---|---|
| `/thermal/image` | `sensor_msgs/msg/Image`；明确`bgr8`等实际编码与显示方式 |
| `/thermal/temperature` | 可选`32FC1`温度图；本项目约定摄氏度，单位同时写入元数据；不支持时不发布假数据 |
| `/thermal/frame_metadata` | 自定义结构：设备会话、源序号、时间、格式、渲染配置、无效/校正标志 |
| `/thermal/status` | 在线、断流、设备配置和记录故障 |
| `/rr/window_result` | 窗口ID、RR、计数、状态、身份、质量字段和文件索引 |
| 原有运动/安全接口 | 实际发现后映射里程计、IMU、到站、停车反馈及安全状态；不假定名称或可用性 |

图像、温度和元数据必须可通过设备会话与帧序号对应。检测图像与温度网格之间保存变换和有效区域；配准未知时不能把二者拼成假测温结果。

ROS图像订阅、显示与原始存盘解耦。QoS需与现有发布者匹配并压测；不能把best-effort订阅当作无损档案。以采集端或可靠接收端原始记录为主，rosbag作为机器人状态与消息回放资料，核对两者完整性。

### 3.2 单次测量用Action

建议命名`/rr/measure`。Action适合需要进度反馈、耗时和取消的任务。[4] 下面是字段设计，并非已经安装的`.action`类型。

| 部分 | 字段 |
|---|---|
| Goal | `visit_id`, `farm_id`, `requested_cow_id`, `identity_status`, `mode`, `observation_seconds`, `max_dwell_seconds`, `max_attempts` |
| Feedback | `state`, `attempt_index`, `elapsed_seconds`, `observed_seconds`, `valid_coverage`, `reason` |
| Result | `measurement_status`, `rr_valid`, `rr_bpm`, `breath_count`, `window_start`, `window_end`, `duration_seconds`, `cow_id`, `identity_status`, `quality_flags`, `source_paths`, `estimator_version` |

约定：

- 调用者传来的牛号是待核对身份，不能自动视为画面中的真实牛；核对失败保留匿名窗口。
- 一个设备同时仅接收一个有效测量Goal。重复访问ID要防止重复记账；重试使用不同attempt/window标识。
- `max_dwell_seconds`覆盖稳定等待、采集、重试和必要处理；不得小于一次观测的最低预算。任务超过上限即结束，不无限等待可见鼻孔。
- 测量状态与身份状态分开：可以得到有效匿名RR，但不得记入指定牛的健康档案。
- 不可判定时`rr_valid=false`；JSON/CSV持久化使用null/空值，ROS浮点字段可用NaN配合有效标志，不以0代表呼吸率。
- 正常完成但信号不足可结束Action并返回`insufficient_signal`；设备故障进入ABORTED；人工取消进入CANCELED。业务无结果不等于可绕过安全故障继续走。
- 取消立即停止形成新的有效窗口并记录原因。原始记录受控收尾；不要为等待文件写完阻塞底盘急停。
- 算法计算放在工作线程/进程，不能长期占住负责安全状态与取消请求的回调。

## 4. 到站测量规则

```text
导航到站 -> 确认停止 -> 等待稳定 -> 锁定一头牛
        -> 采集连续窗口 -> 计算与存档 -> 重试或下一站
任何阶段：安全故障/人工取消 -> 结束本次任务并记录原因
```

初始可采用停车后等待3至5秒、观测30或60秒、最多一次重试，作为试采设置而非已验证阈值。稳定必须结合真实速度反馈、IMU或可用的图像运动证据；发出零速度命令或收到到站成功都不足以证明停稳。

车体/云台移动、切换牛只、双侧长缺失或时钟不连续使当前有效窗口中止；保留原始数据并按配置重采。不能靠跟踪坐标外推给看不见的鼻孔补温度，也不能将不连续片段拼成完整30秒。

若某种安全状态无法读取，应按底盘厂商的联调要求处理，不能把未知状态默认为正常。RR模块是观察任务，不是底盘安全控制器。

## 5. 时间轴与算法适配

每帧至少记录`camera_session_id`, `frame_seq`, `source_time`, `source_clock_domain`, `source_time_kind`, `receive_time`, `receive_monotonic_time`, `timestamp_quality`。

- SDK回调时间不自动等于传感器曝光时间；只获得手机回调时间时如实标明，不伪造传感器时间戳。
- ROS图像header使用明确映射到机器人时钟的时间，另存原时钟值和偏移/漂移估计。接收时刻不能直接代替采集时刻。
- 窗口采用已定义的采集时间区间`[start, end)`。完整固定窗按`RR = 60 * count / (end - start)`换算，不能用峰间跨度或平滑后样本数冒充完整观察时长。
- 实际间隔不均时，先保存缺口，再按冻结的短缺口规则处理。未经评估不直接把不规则样本送入等采样FFT。
- 8.7 fps可作为原设备标称参考，部署的计时与掉帧分析依赖实际时间信息，不用固定帧数替代秒数。

当前`scripts/paper_repro_rr.py`仍为离线批处理脚本，含truth时长、truth-calibrated、优化以及针对旧数据的dense peak target分支。部署适配器必须隔离这些工具：

1. 只读取原始输入和事先冻结的模型/配置，不读取人工计数表。
2. 时间窗由采集任务定义，不从人工真值表裁剪；真值表的同窗时长可供离线核对，但不作为实时输入。
3. 不沿用旧数据“优先接近10次”等目标计数规则作为一般牛群先验。
4. 权重和温度映射模型启动时加载一次并记录哈希；保留BGR训练语义。模型文件名不用于推断网络结构。
5. 整窗归一化与双向处理完成后才输出该窗最终值。30秒窗口的推理即使仅耗时几毫秒，也不是几毫秒获得新的30秒RR。

本次未修改这些算法；后续抽取适配器时需增加回放测试，并保留旧实验完整可重现。速度不足先全量录制、异步估计，显示结果所属测量时刻，不静默跳帧或显示过期值为当前结果。

## 6. 与采集任务一起安排的试验

首轮以10至20头可可靠识别的牛作为安装和链路试采，不能把该数量解释为论文所需统计样本量。每头停稳后连续录制2至3分钟，保留到站和离站上下文；按预定规则生成30/60秒窗口，不看预测后挑片段。

| 条件 | 想区分的原因 |
|---|---|
| 三脚架固定机位 | 不含车体影响的现场参照 |
| 车载停车、电源开启 | 安装、残余振动和背景变化 |
| 车载停车、稳定条件触发 | 观测调度能否提高有效测量率 |
| 低速移动，仅科研支线 | 移动、尺度和目标切换的额外影响 |

不同条件每段都配同步参考，不假定同牛前后RR恒定。首版可用人工耳标登记；参考侧腹视频需要第二机位，车头RGB不能默认承担独立呼吸真值。

人工填写`manual_breath_count`仍在窗口标注表，而不是机器人访问日志。每条参考必须对应同一目标、同一起止区间；不确定计数记录区间/可靠性，不能按预测修正。所需表：

- `rr_robot_visit_log_template_20260907.csv`：每次到站访问、模式、尝试序号、结果及数据索引。
- `rr_fieldwork_sessions_template_20260907.csv`：相机/场次/环境信息。
- `rr_fieldwork_windows_template_20260907.csv`：固定窗与人工计数、可靠性。
- `rr_fieldwork_events_template_20260907.csv`：需要细查时的呼吸事件时间与不确定说明。

没有参考、没看清、断流、无牛或身份未知都要保留记录。误差指标与输出覆盖率同时报告；所有尝试保留，不能只呈现重采后的最好结果。同牛、同长视频和重叠窗口禁止跨训练/调参与独立测试集合。

## 7. 实施顺序与验收

| 阶段 | 现在可做的工作 | 通过后才进入下一步 |
|---|---|---|
| A：相机台架 | 当前手机录像导出；SDK取帧与时间格式核对 | 持续数据可回放，无格式和时间含义混淆 |
| B：离线适配 | 定义帧输入与Action契约；后续实现回放入口 | 同一输入可重复；无truth依赖；缺口和目标切换不混窗 |
| C：车载人工停车 | 安装固定相机；登记牛号；同步参考采集 | 上车后的误差、覆盖率、振动与供电有记录 |
| D：ROS 2到站联调 | 连接实际导航接口和测量Action | 完成、超时、取消、断流、写盘失败均正确反馈 |
| E：冻结整路线 | 新牛/新日期，所有访问保留 | RR误差、有效牛数/小时、覆盖率、身份正确率和故障率同时达标 |

电脑到货后再确认ROS发行版、OS、CPU/GPU、驱动、可用存储和与导航并行的资源占用；不为RR模块擅自升级厂家导航环境。模型加速选择依据实测，转换后重验关键点和最终RR。

最低故障测试：相机断开、目标离场、切换牛只、重复/倒退时间戳、机器人移动、身份未知、磁盘不足、慢推理、人工取消和通信超时。验收看结果是否正确拒判与保留证据，不只看能否画出曲线。

尚未完成：官方SDK实机验证、手机传输程序、ROS消息包、Action服务、算法流式适配、车载性能与路线测试。当前完成的是接口和试验设计，原有生产/科研基线保持不变。
